  <h2 id="one-canon">One canon, thirty-nine packages</h2>

Every package is the same shape: a framework-agnostic controller owns the
state, and a thin plugin syncs it into an Alpine store, magic, or directive.

```ts
import Alpine from "alpinejs";
import accordion from "@ailura/alpinejs-accordion";

Alpine.plugin(accordion());

Alpine.start();
```

Because the shape is shared, the documentation is too. Every package page
follows the same order — install, register, a working example, the API table —
so the first page you read teaches you the other thirty-eight.

  <Aside type="tip" title="Where to go from here">
    [Getting Started](/guide/getting-started/) is the mechanical path: install,
    register, call. [Architecture](/guide/architecture/) is the reasoning behind
    the snippet above — the controller lifecycle, the registration guards, and
    the SSR rules. Pick a layer above and start there instead.
  </Aside>
