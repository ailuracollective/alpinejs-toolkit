# @ailura/alpinejs-accordion

<p align="center">

[![bundlephobia minzip](https://badgen.net/bundlephobia/minzip/@ailura/alpinejs-accordion)](https://bundlephobia.com/package/@ailura/alpinejs-accordion)

</p>

> Headless accessible accordion for Alpine.js — `single`/`multiple` modes, `defaultOpen`, roving tabindex, arrow-key navigation and ARIA helpers, built on `@ailura/alpinejs-core`. The controller is framework-agnostic; the plugin exposes it as `$store.accordion`.

## Installation

```sh
pnpm add @ailura/alpinejs-accordion alpinejs
# or
npm install @ailura/alpinejs-accordion alpinejs
```

Requires `alpinejs@^3.0.0` as peer. `@ailura/alpinejs-core` is a **peer
dependency**, not a dependency: no package in this toolkit has a
`dependencies` block, so the host installs it too.

## Usage

### 1. Standalone (framework-agnostic)

```ts
import { createAccordionController } from "@ailura/alpinejs-accordion";

const ctrl = createAccordionController(); // mounted; every mutator is live
ctrl.create("faq", { mode: "single" });
ctrl.createItem("faq", "item-1");
ctrl.open("faq", "item-1");
ctrl.isOpen("faq", "item-1"); // true
ctrl.openIds("faq"); // ['item-1']

ctrl.on("change", (detail) => {
  detail.instanceId; // 'faq'
  detail.openIds; // ['item-1']
  detail.source; // 'user' | 'initialization'
});

// ctrl.destroy() when done — every mutator after it is a silent no-op
```

The controller owns all mutable state and never touches the DOM, so it is safe
to drive from Blade, Livewire, Astro, or plain TypeScript.

### 2. Alpine

```ts
import Alpine from "alpinejs";
import accordionPlugin from "@ailura/alpinejs-accordion";

Alpine.plugin(accordionPlugin());
Alpine.start();
```

```html
<div
  x-data="{ items: ['billing', 'shipping', 'returns'] }"
  x-init="
    $store.accordion.create('faq', { mode: 'single', defaultOpen: 'shipping' });
    items.forEach(id => $store.accordion.createItem('faq', id));
  "
  @keydown="$store.accordion.handleKeydown('faq', $event)"
>
  <template x-for="id in items" :key="id">
    <div>
      <!-- x-bind covers the static ids; the two values that CHANGE need their
           own attribute, because Alpine applies object-form x-bind only once. -->
      <button
        type="button"
        x-bind="$store.accordion.triggerProps('faq', id)"
        :aria-expanded="$store.accordion.isOpen('faq', id)"
        :tabindex="$store.accordion.activeItem('faq') === id ? 0 : -1"
        @click="$store.accordion.toggle('faq', id)"
        x-text="id"
      ></button>

      <div
        x-show="$store.accordion.isOpen('faq', id)"
        x-cloak
        x-collapse
        x-bind="$store.accordion.panelProps('faq', id)"
      >
        Panel content
      </div>
    </div>
  </template>
</div>
```

The plugin registers `$store.accordion` and no directive, no magic and no
`Alpine.data` component — every binding above is a store call.

## API

### Exports

| Export                               | Description                                                                                     | Type       |
| ------------------------------------ | ----------------------------------------------------------------------------------------------- | ---------- |
| `AccordionController`                | Framework-agnostic controller class — owns group state, emits `change`                          | `class`    |
| `createAccordionController`          | Factory — `createAccordionController({ id? }) => AccordionController`; mounts it                | `function` |
| `accordionPlugin`                    | `Alpine.plugin()` factory — `accordionPlugin({ id?, storeKey? }) => PluginCallback`             | `function` |
| `createAccordionStoreFromController` | Wraps an existing controller in an `AccordionStore` and subscribes it to that controller        | `function` |
| `DEFAULT_ACCORDION_STORE_KEY`        | Default `$store` key — `"accordion"`                                                            | `string`   |
| `AccordionControllerOptions`         | `{ id? }` — controller id, generated by `generateId('accordion')` when absent                   | `type`     |
| `AccordionOptions`                   | Per-accordion options — `{ mode?, defaultOpen?, onChange? }`                                    | `type`     |
| `AccordionMode`                      | `'single' \| 'multiple'`                                                                        | `type`     |
| `AccordionItem`                      | A registered item — `{ id, disabled }`                                                          | `type`     |
| `AccordionInstance`                  | One accordion's projected state — `{ mode, open, activeItemId, items, defaultOpen, onChange? }` | `type`     |
| `AccordionChangeSource`              | Discriminator — `'user' \| 'initialization'`                                                    | `type`     |
| `AccordionChangeDetail`              | `change` payload — `{ instanceId, openIds, source }`                                            | `type`     |
| `AccordionStore`                     | The Alpine-facing surface, i.e. everything reachable as `$store.accordion.*`                    | `type`     |
| `CreateAccordionOptions`             | Plugin options — `{ id?, storeKey? }`                                                           | `type`     |
| `AccordionAlpine`                    | Typed view of the `Alpine` instance the plugin uses                                             | `type`     |
| `AccordionPluginCallback`            | `Alpine.plugin()` callback signature — `(alpine: Alpine) => void`                               | `type`     |
| `AccordionEvents`                    | Event map for `controller.on('change', …)` — one key, one payload                               | `type`     |

`AccordionController` also exposes `hasInstance(accordionId)` and
`snapshotInstances()` for adapter sync; neither is on the store.

### Store API

```ts
// Lifecycle — `createItem` is the only one that does not need `create` first
$store.accordion.create("faq", { mode: "single", defaultOpen: "shipping" });
$store.accordion.createItem("faq", "item-1");
$store.accordion.destroyItem("faq", "item-1");
$store.accordion.destroy("faq"); // one accordion
$store.accordion.destroy(); // the whole controller
$store.accordion.destroyAll(); // every accordion, controller still usable

// Open state — silent no-op on an unknown id, unknown item or disabled item
$store.accordion.open("faq", "item-1");
$store.accordion.close("faq", "item-1");
$store.accordion.toggle("faq", "item-1");
$store.accordion.isOpen("faq", "item-1"); // boolean
$store.accordion.openIds("faq"); // string[]

// Roving tabindex
$store.accordion.activeItem("faq"); // string | null
$store.accordion.setActiveItem("faq", "item-1"); // null clears it

// Keyboard
$store.accordion.handleKeydown("faq", $event);

// ARIA helpers
$store.accordion.triggerProps("faq", "item-1");
// → { id: 'faq-trigger-item-1', 'aria-expanded', 'aria-controls': 'faq-panel-item-1', tabindex }
$store.accordion.panelProps("faq", "item-1");
// → { id: 'faq-panel-item-1', role: 'region', 'aria-labelledby', 'aria-hidden' }
```

| Method                              | Description                                                                                                                                                                              |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `create(id, options?)`              | Creates an accordion. Re-creating an id **replaces** it, options and open state included. Emits `change` with `source: 'initialization'`.                                                |
| `createItem(id, itemId, disabled?)` | Registers an item, **creating the accordion if it does not exist** — the one call that works standalone. Re-registering an id only updates `disabled`.                                   |
| `destroyItem(id, itemId)`           | Removes the item. If it was the active item, `activeItemId` is left pointing at it (it is not re-seeded); the roving tabindex just moves to the next keypress.                           |
| `destroy(id)`                       | Drops one accordion and emits `change` for it.                                                                                                                                           |
| `destroy()`                         | Drops every accordion **and** tears down the controller — later mutations are silent no-ops. Prefer `destroyAll()` to keep the controller alive.                                         |
| `destroyAll()`                      | Drops every accordion, controller still usable.                                                                                                                                          |
| `open(id, itemId)`                  | Opens an item. In `single` mode this closes every other item in the group. No-op for an unknown accordion, an unknown item, or a disabled item.                                          |
| `close(id, itemId)`                 | Closes an item. No-op if it was already closed.                                                                                                                                          |
| `toggle(id, itemId)`                | `close()` when open, `open()` otherwise. No-op if the accordion id was never created.                                                                                                    |
| `isOpen(id, itemId)`                | `false` for anything unregistered.                                                                                                                                                       |
| `openIds(id)`                       | Open item ids, `[]` for an unregistered accordion.                                                                                                                                       |
| `activeItem(id)`                    | The roving-tabindex owner, `null` when none is set.                                                                                                                                      |
| `setActiveItem(id, itemId)`         | Moves the roving tabindex. Ignores an unknown or disabled item; `null` clears it.                                                                                                        |
| `handleKeydown(id, event)`          | `ArrowDown`/`ArrowUp` cycle the active item, `Home`/`End` jump to the first/last **enabled** item, and `preventDefault()` on each. Moves `activeItemId` only — it never calls `focus()`. |
| `triggerProps(id, itemId)`          | See [Limitations](#limitations) — the `tabindex` in here does not update under object-form `x-bind`.                                                                                     |
| `panelProps(id, itemId)`            | `role="region"` plus the `id`/`aria-labelledby` pair. Never sets `hidden`.                                                                                                               |
| `instances`                         | `Record<accordionId, AccordionInstance>` — the read-model, reactive.                                                                                                                     |

### Options

Plugin-level:

```ts
interface CreateAccordionOptions {
  id?: string; // controller id — defaults to generateId('accordion')
  storeKey?: string; // $store key — default DEFAULT_ACCORDION_STORE_KEY ("accordion")
}
```

Per-accordion, passed to `create()`:

```ts
type AccordionOptions = {
  mode?: "single" | "multiple"; // default 'single'
  defaultOpen?: string | string[]; // no default
  onChange?: (openIds: string[]) => void; // no default
};
```

| Option        | Default       | Effect                                                                                                                                                         |
| ------------- | ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mode`        | `'single'`    | `'single'` closes the rest of the group when one opens; `'multiple'` lets several stay open.                                                                   |
| `defaultOpen` | —             | Item id (or ids) opened **as their items are registered**, not at `create()` time. In `single` mode an array is truncated to its first id by `createInstance`. |
| `onChange`    | —             | Called with the current `openIds` from `open()` and `close()` only — not from `toggle()` on a no-op, and not from registration or teardown.                    |
| `id`          | generated     | Controller id. Purely an identifier; nothing in the package reads it after construction.                                                                       |
| `storeKey`    | `'accordion'` | `$store` key the plugin registers under. Ignored by `createAccordionController()`.                                                                             |

### Avoiding name collisions

If your application already owns a `$store.accordion` — or another toolkit
plugin registers on that name — rename the integration surface without
touching the controller:

```ts
Alpine.plugin(accordionPlugin({ storeKey: "faq" })); // → $store.faq
```

`storeKey` is the only name to move, and the exported constant
`DEFAULT_ACCORDION_STORE_KEY` keeps the default discoverable from TypeScript.

### Events

```ts
import type { AccordionChangeDetail } from "@ailura/alpinejs-accordion";

ctrl.on("change", (detail: AccordionChangeDetail) => {
  detail.instanceId; // the accordion id — NOT `groupId`
  detail.openIds; // string[], [] once the accordion is being torn down
  detail.source; // 'user' | 'initialization'
});
```

One event, one payload. `source: 'user'` covers `open`, `close`, `toggle`,
`createItem`, `destroyItem` and `setActiveItem`; `source: 'initialization'`
covers `create`, `destroy(id)` and `destroyAll()`. Filter on `instanceId` if
you run more than one accordion.

## Roving tabindex: bind `tabindex` on its own

`triggerProps()` returns a `tabindex` that follows `activeItem()`. Alpine
applies an **object-form `x-bind` exactly once**, so spread into `x-bind` that
value freezes at whatever the state was during init — the whole group then sits
at `tabindex="-1"` and is unreachable by keyboard. Bind the invariant
attributes through the helper and the two that change through their own
attribute:

```html
<button
  x-bind="$store.accordion.triggerProps('faq', id)"
  :aria-expanded="$store.accordion.isOpen('faq', id)"
  :tabindex="$store.accordion.activeItem('faq') === id ? 0 : -1"
  @click="$store.accordion.toggle('faq', id)"
  @keydown="$store.accordion.handleKeydown('faq', $event)"
></button>
```

The same rule applies to `aria-controls`/`aria-labelledby` in
`panelProps()` — they are stable, so they are safe in the object.

## Panel animation

This package is headless and does not animate panels. Use the official
[`@alpinejs/collapse`](https://alpinejs.dev/plugins/collapse) plugin — `x-collapse`
must sit on the **same element** as `x-show`:

```html
<div
  x-show="$store.accordion.isOpen('faq', itemId)"
  x-cloak
  x-collapse
  x-bind="$store.accordion.panelProps('faq', itemId)"
>
  <div class="px-4 py-3">Panel content</div>
</div>
```

Put padding on an **inner** wrapper — vertical padding on the same node as
`x-collapse` prevents the height from reaching `0` and the animation appears
stuck. `panelProps()` does not set `hidden`; visibility stays client-driven via
`x-show`, so add `x-cloak` or the panel flashes before Alpine boots.

## SSR

> State is in-memory and nothing is read from `window` or `document` at import
> time, so the package is safe to import during SSR. Panels are collapsed by
> default; drive visibility with `x-show` on the client, and only use
> `defaultOpen` where the markup is hydrated on the client too.

## Accessibility

- Triggers, via `triggerProps()`: `id`, `aria-expanded`, `aria-controls`,
  `tabindex` (roving)
- Panels, via `panelProps()`: `id`, `role="region"`, `aria-labelledby`,
  `aria-hidden`
- Keyboard, via `handleKeydown()`: `ArrowDown`/`ArrowUp` cycle the active item
  and wrap, `Home`/`End` jump to the first/last enabled item. Disabled items are
  skipped by `handleKeydown()`, `open()` and `toggle()` alike
- Focus: **managed indirectly.** `handleKeydown()` moves `activeItemId`, and
  `triggerProps()` turns that into a `tabindex="0"` on exactly one trigger —
  but nothing calls `focus()`, so a keyboard user has to keep focus inside the
  group for the arrows to do anything. Put `@keydown` on the group container
  and let the browser move focus to the newly `0` trigger
- Reference: [WAI-ARIA Authoring Practices — Accordion pattern](https://www.w3.org/WAI/ARIA/apg/patterns/accordion/)

## Integration

- **@alpinejs/collapse** — the only animation path this package supports; see
  [Panel animation](#panel-animation)
- **@ailura/alpinejs-overlay** — not required, but `overlay.zIndexOf('accordion', id)`
  is how a panel keeps its place when it is teleported out of its own group

## Limitations

- **`toggle()` on an accordion that was never created is a silent no-op.** The
  store has no `register()`; the calls are `create()` and `createItem()`, and
  only `createItem()` implies a missing `create()`. A wrong accordion id
  produces a button that does nothing and no error.
- **`triggerProps().tabindex` does not update under object-form `x-bind`.**
  Bind it as `x-bind:tabindex` or `:tabindex`; see
  [Roving tabindex](#roving-tabindex-bind-tabindex-on-its-own).
- **`panelProps()` omits `hidden` on purpose** — pair it with `x-show` (+ `x-cloak`).
- **In `single` mode, `defaultOpen` given as an array only honours the first
  id** (`createInstance` truncates).
- **`defaultOpen` is applied at item registration, not at `create()`.** An id in
  `defaultOpen` that is never passed to `createItem()` never opens.
- **`onChange` fires from `open()`/`close()` only** — not from `toggle()` when
  it no-ops, and not from `create`/`destroy`/`createItem`/`destroyItem`.
- **`handleKeydown()` moves state, not focus.** No `focus()` call anywhere in
  the package.
- **`destroyItem()` leaves a dangling `activeItemId`** when the removed item was
  the active one; the roving tabindex recovers on the next keypress.
- Stacking, z-index and scroll lock are consumer-owned.
- The package registers **no directive** — there is no `x-accordion:trigger`.
  Every trigger and panel is a store call plus your own element.
